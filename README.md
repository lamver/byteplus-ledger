# byteplus-ledger

Инструменты для контроля расходов BytePlus ModelArk: остатки бесплатных
пакетов, покрытие подпиской, реальные цены и защита от перерасхода.

BytePlus не показывает остаток квоты через API. Эти скрипты восстанавливают
его из детализации биллинга и отвечают на вопросы, на которые консоль
отвечает плохо: сколько осталось бесплатного, какие модели включены и
почему появился счёт сверх подписки.

## Установка

```bash
git clone https://github.com/<user>/byteplus-ledger
cd byteplus-ledger
cp .env.example .env      # вписать ключи
python report.py
```

Нужен только Python 3.9+, без зависимостей.

### Ключи

В `.env`:

```
BP_AK=AKAP...      # Access Key ID, консоль -> Access Control -> API Access Key
BP_SK=...          # Secret Access Key
ARK_API_KEY=ark-...  # ключ Ark, для проверки доступа к моделям
```

`BP_AK`/`BP_SK` нужны для биллинга (подпись HMAC-SHA256).
`ARK_API_KEY` только для `report.py --probe`, `models_check.py` и `bench.py`.

## Команды

| Скрипт | Что показывает |
|---|---|
| `report.py` | общая сводка: баланс, расход по месяцам и моделям, каталог |
| `report.py --probe` | плюс реальная проверка доступа к каждой модели |
| `quota.py` | остатки бесплатных пакетов с прогресс-барами |
| `spend.py 2026-08` | расход по месяцам |
| `detail.py 2026-08` | разбивка по элементам и токенам |
| `coverage.py 2026-08` | покрытие подпиской по моделям |
| `guard.py [месяц] [порог]` | сторож, exit 1 при перерасходе |
| `live.py [часов]` | расход в реальном времени по 5-минутным окнам |
| `bench.py` | тест качества кода + учёт токенов |
| `models_check.py` | какие модели открыты по ключу |

## Как это работает

BytePlus отдаёт детализацию через `ListBillDetail` (billing API,
`open.byteplusapi.com`, подпись Volcengine HMAC-SHA256). Ключевые поля:

- `Count` — сколько израсходовано
- `DeductionCount` — сколько списано из пакета (то есть бесплатно)
- `PretaxAmount` — сколько пришлось оплатить деньгами
- `BillCategory` — `Consumption-purchase` это выдача пакета,
  `Consumption-usage` это расход

Остаток пакета = выданное количество минус сумма `DeductionCount`.
Как только вычет перестаёт расти, а `PretaxAmount` идёт вверх, пакет кончился.

## Главное: подписка живёт на отдельном endpoint

Если у вас куплен Coding Plan, обращаться нужно к `/api/coding/v3`
(или `/api/coding` для Anthropic-совместимых клиентов), а модель
указывать как `ark-code-latest`.

Обычный `/api/v3` идёт **мимо подписки** и тарифицируется отдельно,
даже когда план оплачен и активен. Подробности в [ACCOUNT.md](ACCOUNT.md).

## Как не платить сверх подписки

Отдельного переключателя «запретить overage» в BytePlus нет. Рабочая схема:

1. Убедиться, что клиенты ходят на `/api/coding/v3`, а не на `/api/v3`.
2. Держать `AvailableBalance = 0` и `CreditLimit = 0`. Списать overage
   не с чего, он копится задолженностью, а pay-as-you-go отключается.
3. Не включать автопополнение баланса.
4. Повесить `guard.py` в планировщик. При появлении расхода сверх
   подписки он вернёт exit 1 и покажет уведомление.

Для Windows есть `guard_run.cmd`:

```cmd
schtasks /Create /TN "BytePlusGuard" /TR "%CD%\guard_run.cmd" /SC HOURLY /F
```

Порог задаётся переменной `BP_GUARD_LIMIT` (по умолчанию 1.20). Он нужен,
когда часть долга уже накоплена и разбирается отдельно: сторож тогда
молчит про старое и реагирует только на новый расход.

## Замечания по BytePlus API

Собрано опытным путём, в документации этого нет:

- `/api/v3/subscriptions`, `/api/v3/quota`, `/api/v3/coding/usage`
  возвращают HTTP 200 с **пустым телом**. Это заглушки, не данные.
- `ListResourcePackages` существует, но `ResourceType` не принимает
  ни одно из проверенных значений. Пакеты приходится доставать
  из `ListBillDetail`.
- `MaxResults` в этом методе требуется строкой, не числом.
- STS-токены вида `VxCg...` проходят на `/models`, но дают 401
  на `/chat/completions`. Для биллинга они бесполезны.
- `ListBillDetail` требует и `GroupPeriod`, и `GroupTerm`.
