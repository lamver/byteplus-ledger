# Что доступно на BytePlus ModelArk

## Главное: два разных endpoint

Самая дорогая ошибка при работе с Coding Plan. Подписка обслуживается
**отдельным адресом**, и обычный API идёт мимо неё:

| Endpoint | Что делает |
|---|---|
| `/api/coding/v3` | OpenAI-совместимый, **внутри подписки** |
| `/api/coding` | Anthropic-совместимый, **внутри подписки** |
| `/api/v3` | обычный API, **тарифицируется отдельно** |

В консоли это написано одной строкой мелким шрифтом:
«Do not use `/api/v3`, access will incur additional charges».

Признак, что вы платите зря: счётчики плана в консоли стоят на нуле,
а в биллинге растёт `Pay-as-you-go`.

На endpoint подписки нужно указывать модель **`ark-code-latest`**.
Это авто-роутер, он сам выбирает модель по связке качество и скорость.
Ответ приходит с полем `"model": "auto"`.

## Лимиты подписки

Внутри плана лимиты не токенные, а по временным окнам:

- лимит текущей сессии, окно около 5 часов
- 7-дневный лимит
- 30-дневный лимит

Смотреть в консоли: Subscription → Coding Plan → Usage. Через API эти
счётчики недоступны, `/api/v3/subscriptions` и подобные отдают пустое тело.

## Модели через Coding Plan

Проверено реальными запросами (`coding_check.py`), работают:

| Модель | Заметки |
|---|---|
| `ark-code-latest` | авто-роутер, рекомендуемый вариант |
| `seed-2-0-code-preview-260328` | заточен под агентское кодирование |
| `seed-2-0-pro-260328` | длинные цепочки рассуждений |
| `seed-2-0-lite-260228` | баланс качества и скорости |
| `deepseek-v4-pro-260425` | сильная математика и код |
| `deepseek-v4-flash-260425` | быстрее и дешевле |
| `glm-5.2` | контекст 1M |
| `glm-5-1-260408` | длинные автономные задачи |
| `kimi-k2-5-260127` | мультимодальный, UI и код |
| `gpt-oss-120b-250805` | открытые веса OpenAI |

Не работают на этом endpoint: `auto` (нужно писать `ark-code-latest`)
и `seed-1-6-code-preview`, оба дают `UnsupportedModel`.

Через план доступны модели, которые по прямому `/api/v3` отвечают
`ModelNotOpen`. Активировать их отдельно не нужно.

## Скорость

На одинаковых задачах endpoint подписки оказался в 5-8 раз быстрее
прямого API: 2.3-2.9 секунды против 12-20 секунд. Вероятно, за счёт
роутинга на менее загруженные модели.

## Бесплатные пакеты (прямой API)

Выдаются при активации модели в обычном `/api/v3`, срок жизни около
двух лет. К подписке отношения не имеют.

| Пакет | Объём |
|---|---|
| DeepSeek-V4-pro-0813 | 500K токенов |
| DeepSeek-V4-pro | 500K токенов |
| DeepSeek-V4-flash-0731 | 500K токенов |
| GLM-5.2 | 500K токенов |
| Seedance-1.5-pro (видео) | 2 000K токенов |
| Seedream 4.5 (изображения) | 200 штук |
| Seedream 5.0-Lite | 50 штук |

Проверить остаток: `python quota.py`.

## Цены прямого API (сверх пакетов)

За 1K токенов, USD. Это фактические ставки одного аккаунта, у вас могут
отличаться.

| Модель | Prompt | Completion | KV-cache hit |
|---|---|---|---|
| DeepSeek-V4-pro-0813 | 0.001320 | 0.003960 | 0.000044 |
| DeepSeek-V4-pro | 0.001740 | 0.003480 | — |
| DeepSeek-V4-flash-0731 | 0.000440 | 0.001320 | — |
| GLM-5.2 | 0.001400 | 0.004400 | 0.000260 |

| Прочее | Цена |
|---|---|
| Seedance-1.5-pro, видео без звука | 0.001200 / 1K токенов |
| Seedance-1.5-pro, видео со звуком | 0.002400 / 1K токенов |
| Seedream 4.5, генерация или правка | 0.040000 / изображение |

Осторожно с агентской нагрузкой на прямом API: замеренный темп
достигал 12M токенов в час, из них около 95% это KV-cache
разрастающегося контекста. Это порядка 1 USD в час.

## Как читать биллинг

Полезные поля `ListBillDetail`:

- `DeductionCount` больше нуля — расход покрыт пакетом, денег не стоит
- `PretaxAmount` больше нуля — оплачено деньгами
- `BillingMode = Yearly/monthly` — подписка или выдача пакета
- `BillingMode = Pay-as-you-go` — поштучный расход
- `BillCategory = Consumption-purchase` — выдача пакета
- `BillCategory = Consumption-usage` — расход
- `InstanceNo` — идентификатор источника, помогает найти,
  какой именно агент жжёт токены

Признак исчерпания пакета: `DeductionCount` перестал расти, а
`PretaxAmount` пошёл вверх.
